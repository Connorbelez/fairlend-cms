# FairLend Build Model — Four Content Concepts

**Section:** Our Build Model  
**Primary audience:** GTA property owners, small-scale builders, infill developers, and first-time builders  
**Job of the section:** Explain FairLend's full build-financing role, differentiate the company from a conventional mortgage broker or construction lender, and make the next step feel lower-risk.  
**Frameworks used:** StoryBrand for the lifecycle spine; PAS for fragmentation and risk; AIDA for section progression.

## Strategic correction

The section should not read as four lists of services. A list tells visitors what FairLend can touch; it does not explain why having one team across the whole project changes the outcome.

The stronger story is:

> Most firms enter at one transaction. FairLend helps connect the decisions that make the entire project work—from what the site can support, through capital and construction draws, to the exit the financing depends on.

Keep **Plan → Finance → Build Support → Takeout** as the four-stage lifecycle. Treat the **Unf\*ck Contingency Program** as a safety net within Build Support or as a secondary proof panel after the lifecycle. Recovery is a capability, not a stage every successful project should expect to enter.

Any reference to CMHC or MLI Select should remain qualified with language such as **“where the project and borrower are eligible”** or **“where appropriate.”** FairLend supports the permit and approval path; it does not issue or guarantee permits, approvals, funding, project completion, or takeout financing.

# Concept 1 — One Team. One Project Model. Every Stage.

**Recommended direction**

## Why it works

This is the clearest expression of the one-stop-shop differentiator. It positions FairLend as the operating layer connecting development decisions and financing decisions—not as a broker with a longer service menu. Each stage answers three questions: what is being decided, what FairLend does, and what the client carries forward.

## Layout

Use four full-width lifecycle rows rather than four equal bullet cards. Each row contains:

- A stage number and outcome-led headline
- A short explanatory paragraph
- A compact **“We connect”** line
- A concrete **“You leave with”** deliverable
- A handoff cue showing how the output becomes the input to the next stage

On desktop, alternate copy and a project-file visual. On mobile, stack each row as a self-contained chapter. Finish with a narrow recovery-support callout and CTA.

## Section copy

**Eyebrow:** Our Build Model

**Headline:** One team from first feasibility to final takeout.

**Lead:** A build is not four separate problems. The site, scope, budget, financing, draw schedule, approvals, and exit all depend on one another. FairLend brings them into one working model so decisions made early still make sense when it is time to fund, build, and refinance or sell.

### 01 — Plan

**Headline:** Start with a project the numbers can support.

**Body:** Before more capital is committed, we help test the site and intended build against the realities that will shape financing: acquisition basis, zoning and housing form, unit mix, buildable area, hard and soft costs, contingency, timeline, and expected exit.

**We connect:** Site feasibility · development scope · preliminary budget · approval path · exit assumptions

**You leave with:** A financeable project brief that shows what must be true for the opportunity to move forward.

**Handoff:** The plan becomes the basis for the capital structure—not a separate document the lender sees later.

### 02 — Finance

**Headline:** Structure capital around the way the build will actually happen.

**Body:** We bring the land basis, construction budget, borrower equity, working-capital needs, milestones, and exit into the same financing model. Then we arrange an appropriate mortgage structure and map when capital needs to be available—not merely how much is approved on paper.

**We connect:** Acquisition and bridge needs · borrower capital · construction financing · milestone draws · financing costs · contingency

**You leave with:** A capital and draw plan aligned to the project schedule, with costs, conditions, and borrower obligations made clear.

**Handoff:** The financing plan becomes the operating cash-flow plan for the build.

### 03 — Build Support

**Headline:** Keep the file, funding, and site moving together.

**Body:** Construction financing does not end at closing. We help coordinate the documentation and milestone evidence behind draw releases, maintain visibility into progress and budget drift, and connect borrowers with appropriate consultants, trades, suppliers, construction managers, or recovery resources when needed.

**We connect:** DrawFlow administration · milestone documentation · site visibility · permit-readiness support · professional introductions · issue escalation

**You leave with:** A current project file that supports draw decisions, flags gaps early, and keeps the takeout requirements visible while work is underway.

**Handoff:** Every draw and project update strengthens the evidence needed for the exit.

### 04 — Takeout

**Headline:** Build toward the exit from day one.

**Body:** Sale, refinance, or rental stabilization should not become a maturity-date scramble. We identify the intended takeout early, track the conditions it depends on, and prepare the financing path as the project approaches completion—including insured takeout options such as MLI Select where the project and borrower are eligible.

**We connect:** Completion evidence · updated value and income · rental stabilization · sale or refinance strategy · long-term financing requirements

**You leave with:** A defined exit path, a readiness checklist, and a financing file prepared for the next transaction.

### Recovery support callout

**Headline:** If the project drifts, the plan does not disappear.

**Body:** Our Unf\*ck Contingency Program helps diagnose problems across schedule, budget, trades, working capital, and documentation, then coordinates an appropriate recovery path. It is practical support in a difficult moment—not a guarantee of cost, timing, contractor performance, completion, or recovery.

### Closing copy

**Headline:** One accountable thread through the entire project.

**Body:** You do not have to assemble the full team or solve every financing question before speaking with us. Bring the property, plan, or early idea. We will help determine what the project needs next and whether FairLend is the right fit.

**CTA:** Book a build consultation

**CTA microcopy:** Your first conversation is on us. No finished plan required.

# Concept 2 — Four Expensive Handoffs, Removed

## Why it works

This concept leads with the enemy: fragmentation. It makes the one-stop-shop model valuable by showing the cost of disconnected advisors, assumptions, lenders, and project files. The section does not say “we do everything”; it shows where handoffs typically break and how FairLend maintains continuity.

## Layout

Use a two-column comparison across four horizontal bands:

- **When the process is fragmented** — the common failure mode
- **With FairLend across the project** — the connected response

The centre rail carries one continuous project line from site to exit. Add a small **“continuity record”** at the bottom of each band showing what is preserved for the next stage.

## Section copy

**Eyebrow:** One Connected Build-Financing Process

**Headline:** The gaps between advisors are where projects lose time and money.

**Lead:** The planner may not know the lender's constraints. The lender may not see the draw pressure coming. The draw file may not be organized for takeout. FairLend keeps one project model moving across every stage so the next decision starts with the full context—not a cold handoff.

### 01 — Plan

**Fragmented process:** The site is selected, the design advances, and the budget hardens before anyone tests whether the capital structure and exit can support them.

**FairLend response:** We review the land basis, intended housing form, unit mix, buildable area, preliminary budget, approval path, timeline, and exit assumptions together—while the project can still be shaped.

**Continuity record:** Feasibility assumptions documented for financing.

### 02 — Finance

**Fragmented process:** A lender approves an amount, but the borrower still has to reconcile equity timing, deposits, trade payments, interest carry, holdbacks, and the gap between draws.

**FairLend response:** We structure the mortgage financing around the project budget and sequence of work, then build a milestone draw plan that accounts for borrower capital and working-capital needs.

**Continuity record:** Capital stack, draw conditions, and borrower obligations in one model.

### 03 — Build Support

**Fragmented process:** The transaction closes and the broker disappears. The builder is left coordinating consultants, site evidence, draw requests, lender questions, and emerging budget problems alone.

**FairLend response:** We stay involved through draw administration, documentation, milestone visibility, professional introductions where appropriate, and early escalation when schedule, budget, trades, or working capital begin to drift.

**Continuity record:** A current build file that records progress, conditions, and unresolved risks.

### 04 — Takeout

**Fragmented process:** Refinance or sale planning starts near maturity, when missing documents, incomplete work, unstable income, or changed valuations are hardest to solve.

**FairLend response:** We define the intended exit early and keep its requirements in view through the build, preparing for sale, refinance, rental stabilization, or eligible insured takeout as completion approaches.

**Continuity record:** A takeout-ready file instead of a last-minute reconstruction.

### Differentiator close

**Headline:** Four handoffs become one working relationship.

**Body:** FairLend combines mortgage brokerage, construction-financing strategy, administration infrastructure, and build advisory support in one practical operating layer. That continuity is the product.

**CTA:** Map my project path

**CTA microcopy:** Start with the stage you are in. We will connect it to what comes next.

# Concept 3 — The Four Decisions Every Build Must Survive

## Why it works

This direction replaces service bullets with decision confidence. Visitors recognize the questions keeping them up at night, then see how FairLend helps answer each one. It is strongest for experienced builders who do not need generic education but do want evidence of construction-financing judgment.

## Layout

Use a four-panel decision-gate system. Each panel has:

- The high-stakes question
- What FairLend tests
- The evidence required to advance
- The risk of skipping the gate

The panels can fill the existing area with ledgers, status chips, and checklists rather than short bullet points. A progress indicator changes from **Question → Tested → Ready** as the user moves through the section.

## Section copy

**Eyebrow:** Four Decisions. One Build Model.

**Headline:** A project is ready when its critical assumptions agree.

**Lead:** Good builds fail when land, scope, capital, construction, and exit are evaluated in isolation. Our role is to pressure-test the decisions that connect them—and help build a financing path that can hold together from acquisition through takeout.

### Gate 01 — Plan

**The decision:** Is this the right project for this site and this capital base?

**What we test:** Acquisition basis, zoning fit, housing form, unit mix, buildable area, preliminary hard and soft costs, contingency, timeline, end value, and intended exit.

**Ready means:** The project scope and budget are grounded enough to structure financing and identify the major approval, cost, and execution risks.

**If skipped:** The borrower can become committed to land or design assumptions the financing cannot support.

### Gate 02 — Finance

**The decision:** Will the right capital be available at the right milestones?

**What we test:** Borrower equity, acquisition and bridge needs, lender fit, construction facility, draw sequence, holdbacks, interest carry, working capital, and contingency capacity.

**Ready means:** The sources and uses balance, the draw plan matches the build sequence, and the borrower understands the costs, conditions, and capital obligations.

**If skipped:** A project can be fully “funded” on paper and still run short of usable cash between milestones.

### Gate 03 — Build Support

**The decision:** Can progress be documented and problems surfaced early enough to act?

**What we track:** Milestone evidence, draw documentation, site progress, budget and schedule drift, permit-readiness items, lender conditions, and emerging trade or working-capital constraints.

**Ready means:** Draw requests have a clear evidentiary path, open issues have owners, and the project file reflects what is actually happening on site.

**If skipped:** Missing documents, delayed draws, and small variances can compound into expensive project-level problems.

### Gate 04 — Takeout

**The decision:** What event repays the construction financing—and what must be true for it to happen?

**What we prepare:** Sale, refinance, stabilized rental income, completion and occupancy evidence, updated valuation inputs, long-term lender requirements, and insured takeout readiness where eligible.

**Ready means:** The borrower knows the intended exit, its dependencies, the documentation still required, and the alternatives if conditions change.

**If skipped:** The takeout becomes a deadline instead of a managed transition.

### Closing copy

**Headline:** We do not just arrange the loan. We help connect the decisions it depends on.

**Body:** FairLend stays focused on the whole equation: what can be built, how it will be funded, how progress will be supported, and how the construction capital will be repaid.

**CTA:** Pressure-test my project

**CTA microcopy:** Bring the assumptions you have. We will help identify the ones that still need work.

# Concept 4 — Your Project File, Built Forward

## Why it works

This concept makes FairLend's continuity tangible. Instead of abstractly claiming “end to end,” it shows a project file accumulating useful work product at every stage. It also aligns best with the existing sticky dossier-board visual and can likely be implemented with less structural disruption than the other concepts.

## Layout

The left-side project dossier stays persistent. Each stage adds documents, decisions, and status information to the file. The right side uses three content blocks rather than a four-item bullet grid:

- **What we work through**
- **What is added to your file**
- **Why the next stage is easier**

Use six dossier tabs: Parcel, Budget, Approvals, Draws, Risk, Takeout. The recovery program can appear in the Risk tab without interrupting the four-stage lifecycle.

## Section copy

**Eyebrow:** One Project File From Site To Exit

**Headline:** Every stage should make the next one easier.

**Lead:** Your project should not restart every time a new professional or lender enters the room. FairLend builds the financing file forward—carrying the assumptions, decisions, documents, and conditions from planning into funding, from funding into construction, and from construction into takeout.

### 01 — Plan / Open the file

**Headline:** Turn the property and idea into a testable project.

**What we work through:** The site, acquisition basis, zoning and housing form, unit mix, buildable area, preliminary budget, approval path, timeline, expected value, and intended exit.

**Added to your file:** Parcel and feasibility summary · project assumptions · preliminary sources and uses · approval and documentation gaps · initial exit thesis

**Why the next stage is easier:** Financing begins with a coherent project brief instead of disconnected plans, estimates, and expectations.

### 02 — Finance / Build the capital file

**Headline:** Match the financing structure to the project sequence.

**What we work through:** Borrower capital, acquisition or bridge requirements, construction costs, contingency, lender fit, facility structure, milestone draws, interest carry, working capital, and material financing conditions.

**Added to your file:** Capital-stack summary · milestone draw schedule · borrower-capital plan · financing-cost view · condition and obligation checklist

**Why the next stage is easier:** The builder can see when funds are expected, what must be completed or documented, and where their own capital enters the sequence.

### 03 — Build Support / Keep the file current

**Headline:** Make site progress legible to the financing process.

**What we work through:** DrawFlow submissions, milestone evidence, site and budget updates, lender documentation, permit-readiness items, consultant coordination, and emerging schedule, trade, or working-capital issues.

**Added to your file:** Draw history · progress evidence · open-condition tracker · issue and escalation log · updated takeout-readiness items

**Why the next stage is easier:** The exit file is assembled during the build rather than reconstructed under a maturity deadline.

### 04 — Takeout / Complete the file

**Headline:** Convert construction progress into an executable exit.

**What we work through:** Completion status, occupancy and other required evidence, updated value and income, rental stabilization, sale or refinance timing, long-term lender requirements, and eligible insured takeout options.

**Added to your file:** Exit-readiness checklist · completion and operating evidence · updated financing package · outstanding-condition plan · alternate-path summary

**Why the transition is easier:** The intended exit and its requirements have been visible throughout the project—not introduced at the end.

### Dossier footer

**Headline:** The file changes. The team does not.

**Body:** FairLend carries the project context across planning, mortgage placement, draw-stage administration, build support, and takeout preparation. When something changes, the downstream impact is visible to the same team helping you respond.

**CTA:** Open my project file

**CTA microcopy:** Property, drawings, budget, or early idea—start with what you have.

# Recommendation

Choose **Concept 1 — One Team. One Project Model. Every Stage.**

It is the strongest balance of immediate comprehension, differentiated positioning, and practical detail. It speaks equally well to first-time and experienced builders, preserves the four lifecycle labels already present in the interface, and gives the design enough structured content to use the space without turning the section into a dense service catalogue.

Use the persistent dossier visual treatment from **Concept 4** inside Concept 1. That combination gives the section a clear verbal thesis and tangible proof that FairLend carries one working project model from site selection to takeout.

## Recommended final information architecture

1. Section thesis: **One team from first feasibility to final takeout.**
2. Four lifecycle rows using **Decision / FairLend role / Deliverable / Handoff**.
3. Persistent project dossier that visibly accumulates work product.
4. Recovery-support inset inside Build Support, not a fifth equal lifecycle stage.
5. Closing differentiator: **One accountable thread through the entire project.**
6. CTA: **Book a build consultation.**

This structure uses the available space to explain the operating model, answer objections, and make the one-stop-shop claim concrete instead of merely repeating more service bullets.
